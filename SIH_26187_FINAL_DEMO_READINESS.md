# Demo Readiness

## Judge-Day Clean Demo Environment

The judge-day path uses a separate fresh SQLite database at
`data/demo/sih_demo.db`, migrated to Alembic head and initialized through the
normal bootstrap flow. The development/forensic database is archived under
`data/archive/` and is not mixed into this dataset. The reset procedure is
`scripts/reset_sih_demo.ps1`; it requires process-provided passwords and never
embeds credentials. New evidence is generated by the normal two-camera edge
flow. Historical development evidence, including genuine broken segments, is
not claimed to be valid in the clean demo environment.

The native Windows two-camera demo is the authoritative SIH path. It is
DEMO STABLE when run with the repository clip and bounded two-camera workflow;
performance is CPU-limited and should be presented honestly.

# Verified Capabilities

- Two independent local-video EdgePipeline workers
- YOLO, ByteTrack, rules, events, signed evidence, telemetry, WebSocket
- Authentication/RBAC, alerts, correlation, ANPR/face/night functional paths
- Offline queue/recovery and protected evidence access

# Partially Verified Capabilities

- ANPR accuracy and face recognition accuracy require controlled/labeled data.
- Night delivery browser closure remains partial.
- Extended memory/restart stress is incomplete.
- RTSP adapter semantics are tested, but no live RTSP server is available.

# Externally Blocked Capabilities

Docker/PostgreSQL/MinIO, browser RTSP preview, physical CCTV, and GPU
performance are not validated on this host.

# Performance Summary

Measured CPU-only: one stream 1.05 FPS; two streams 0.60 FPS per camera;
four-stream run degraded to one frame per worker with ~6-second frame latency.

# Security Summary

Webhook SSRF policy/signing, bounded uploads, login throttling, protected media,
path confinement, CORS, and existing RBAC controls are documented in the
security-hardening report.

# Exact SIH Demo Flow

Start the native launcher, run the smoke check, log in, start both cameras, show
telemetry/tracks, wait for a real event, open reliability/alerts/evidence, then
show ANPR, Face Watchlist, night, correlation, and System Health with their
documented evidence boundaries.

# Startup Procedure

Run `start_netraksh.cmd`, then `powershell -File scripts/demo_smoke.ps1` with
`NETRAKSH_DEMO_USERNAME` and `NETRAKSH_DEMO_PASSWORD` set.

# Emergency Recovery Procedure

Stop and restart only the affected named worker. If backend recovery is needed,
restart the backend and allow the edge outbox to drain; do not delete databases,
keys, evidence, or watchlist data.

# Safe Claims

Claim executed two-camera local full inference and bounded offline evidence
recovery. Claim functional ANPR/face/night architecture only within the reports.

# Claims Not To Make

Do not claim GPU throughput, physical CCTV compatibility, PostgreSQL/MinIO
execution, night accuracy, or large-camera scalability.

# Known Limitations

CPU-only inference, absent Docker/RTSP tooling, incomplete long-duration stress,
and partial browser night closure remain.
