# Production UI truth audit

This document classifies every production route by the authority behind each displayed fact. The UI must use `N/A`, `NOT REPORTED`, `IDLE`, or an explicit configuration/capability label when no authoritative runtime record exists. It must not substitute a value from another camera, stream, analysis run, or environment.

## Route audit

| Route/surface | Authoritative sources | Truth classification and remediation |
|---|---|---|
| Global header | `/health`, `/system/status`, `/sync/status`, WebSocket, coordinated startup snapshot | `REAL_RUNTIME` / `REAL_DATABASE`. Command identity is returned by the backend. Sync is `IDLE` until real activity exists; zero queue alone is not `CURRENT`. |
| `/` Command Center | `/cameras`, `/api/dashboard/video/current`, current-run WebSocket telemetry/events, edge `/wake` health payload | `REAL_RUNTIME` / `REAL_DATABASE`. Removed static camera names, demo-slot labels, capability claims, and route-load analysis start. Node, source, analysis, and telemetry are independent states. |
| `/map` | Registered `Camera.latitude/longitude`, camera health, current telemetry, real events | `REAL_DATABASE` / `REAL_RUNTIME`. No coordinates means `NO REGISTERED CAMERA LOCATION`; the map default is never presented as a deployment site. |
| `/camera-health` | `/ready`, `/system/status`, `/system/capabilities`, `/sync/status`, `/cameras`, WebSocket, startup readiness | `REAL_RUNTIME` / `REAL_CONFIGURATION`. Includes backend, DB, WebSocket, storage durability, ledger mode, node, analysis, telemetry, and camera measurement state. |
| `/evidence` | Evidence APIs and chain verification API | `REAL_DATABASE`. Empty state stays empty. Mock blockchain receipts must remain labelled simulated. Local filesystem evidence is non-durable. |
| `/cross-command-alerts` | `/alerts`, WebSocket, `/system/capabilities`, authenticated user command server-side | `REAL_DATABASE` / `CAPABILITY`. Removed unconditional security/corroboration claims and client-supplied command identity. |
| `/performance` | `/system/metrics`, WebSocket telemetry, startup readiness | `REAL_RUNTIME` / `HISTORICAL`. A fresh worker metrics report is not active analysis. FPS is shown as current only with current-run live telemetry. |
| `/watchlist` | Watchlist APIs | `REAL_DATABASE` / `CAPABILITY`. Classical recognition limitations and human-review requirement remain explicit. |
| `/camera-management` | Camera APIs | `REAL_DATABASE`. Form placeholders are input guidance, not operational facts. |
| `/architecture` | `/system/capabilities` plus documented implementation | `CAPABILITY` / `REAL_CONFIGURATION`. Durable storage and ledger mode are runtime-derived; mock mode is labelled simulated. |
| `/analytics` | Analytics APIs | `REAL_DATABASE`. Empty aggregates remain zero/empty without generated rows. |
| `/audit` | Audit APIs | `REAL_DATABASE`. No placeholder history. |
| Login/startup gate | Coordinated backend and two-edge readiness probes | `REAL_RUNTIME`. Wake probes do not start analysis, upload video, or generate telemetry/evidence. |

## Field lineage

| Displayed field | Frontend consumer | Transport field | Durable/origin source | Scope rule |
|---|---|---|---|---|
| AI FPS | Dashboard, Performance | `processing_fps`, metrics `fps` | Edge measured processing window / `pipeline_metrics` | Current only when telemetry belongs to the exact current analysis session; otherwise historical or `N/A`. |
| Source FPS | Dashboard | `source_fps` | Video capture metadata measured by edge | Exact source/run only. |
| Frame index | Dashboard/video | `frame_index` | Edge telemetry and analyzed-frame cache | Exact `analysis_session_id` and frame identity. |
| Persons / vehicles / tracks | Dashboard | `person_count`, `vehicle_count`, `track_count` | Edge telemetry | Exact camera and current analysis session. |
| Scene condition | Dashboard | `scene_condition`, `lighting_state` | Edge scene-condition pipeline / event snapshot | Current telemetry or exact event snapshot; no global fallback. |
| Camera health | Dashboard, Health, Map | `health_state`, `health_reason`, measured FPS/quality | Latest `camera_health` row and live health payload | Camera-specific, with freshness shown separately. |
| ANPR plate/confidence | Dashboard | `normalized_plate_text`, `plate_text`, `plate_confidence` | Exact event generated by ANPR pipeline | No event means “No plate evaluated” or capability-based unavailable. |
| Face status/score | Dashboard, Watchlist | `face_match_status`, subject fields, `recognition_score` | Exact event and watchlist records | Exact event/run; classical engine limitations remain visible. |
| Latest event | Dashboard, Map | event payload and IDs | `events` table / WebSocket event | Camera + source stream + analysis session scoped. No cross-camera “latest” substitution. |
| Decision / severity | Dashboard, Alerts | `decision_state`, `decision_reason`, `severity` | Immutable event/alert snapshot | Exact event record only. |
| Reliability D/T/S/H/R | Dashboard | `score_d`, `score_t`, `score_s`, `score_h`, `score_r` | Event snapshot produced by reliability engine | All factors come from the same event. |
| Evidence | Evidence route | evidence package fields | `evidence_packages` and referenced bytes | No fake package/receipt. Availability and durability are separate. |
| Chain verification | Header/Evidence | `/system/verify-chain` | Evidence chain rows | On-demand result; absence means no evidence, not proof of an external ledger. |
| Sync queue | Header/Health | queue, sent, failed, `has_activity`, `last_activity_at` | Edge metrics and `sync_queue` | `IDLE` before any real activity; failures are never collapsed into current. |
| Pipeline metrics | Performance | `/system/metrics`, metrics WebSocket | `pipeline_metrics` | Report timestamp controls current vs historical; process readiness is separate from analysis. |

## Identity and session boundaries

- `camera_id` identifies a registered camera/edge slot.
- `stream_id` identifies the selected durable source session.
- `analysis_session_id` identifies one concrete inference run over a source.
- `analysis_generation` prevents old in-flight telemetry from a prior run from being accepted as current.
- The UI may join records only when these available identities agree. Missing identity is rendered as unavailable, not guessed.

## Known production blockers

- `OBJECT_STORAGE_PROVIDER=local` is ephemeral on Render and is not durable evidence storage. The capability endpoint reports `BLOCKED_NON_DURABLE_LOCAL` until legitimate S3-compatible storage is configured.
- `BLOCKCHAIN_MODE=mock` is simulated. It does not prove Fabric or another production blockchain is available.
- Real-video validation has not been authorized in this phase. No camera analysis, upload, or analysis session is created by this audit.
